## Outcome

P2 adds one auditable command-line entry point for training or loading four
Stable-Baselines3 PPO variants:

- `vanilla_ppo`: native clean PPO baseline;
- `adv_ppo`: maintained adversarial-training engineering baseline;
- `sa_ppo`: clean-room SA-PPO objective with a maintained PGD inner solver;
- `car_ppo`: clean-room discrete CAR-PPO objective with finite PGD.

Every run writes `model.zip` and a machine-readable `manifest.json` containing
the resolved robust-training configuration, PPO hyperparameters, package
versions, model hash, clean evaluation cohort/results, and final training
metrics.

P2 also provides an evaluation-only interval-bound propagation component for
certifying whether a supported MLP actor's greedy action is invariant in a
local input box. It is deliberately not labeled an IBP-trained PPO defense.

## Fidelity and isolation boundary

Only Vanilla PPO is a native SB3 baseline. `sa_ppo` and `car_ppo` are
clean-room objective/style implementations; they are not paper-exact
reproductions. In particular:

- SA-PPO uses the maintained PGD solver rather than the original legacy
  SGLD/convex-relaxation stack.
- CAR-PPO uses per-sample PGD followed by the paper's detached soft weighting
  across the minibatch. The maintained port targets categorical SB3 policies;
  it is not the legacy continuous-control implementation and provides no
  certificate.
- Adv-PPO is a declared engineering baseline, not a claim that one uniquely
  defined paper algorithm has been reproduced.

The locked `SA_PPO` and `CAR-RL` repositories remain reference-only under
`third_party/upstream-lock.json`. The maintained package never imports them at
runtime. Their root licenses are unresolved at the pinned commits, so P2 does
not copy their source code.

Paper-code fidelity checks, when required, run in isolated legacy environments
and are reported separately from clean-room SB3 results.

## CLI

Train a new baseline:

```powershell
rl-attack-defense `
  --method sa_ppo `
  --env-id CartPole-v1 `
  --timesteps 100000 `
  --epsilon 0.02 `
  --attack pgd `
  --attack-steps 10 `
  --attack-step-size 0.005 `
  --attack-random-start `
  --policy-consistency-coef 1.0 `
  --seed 0 `
  --output-dir outputs/p2_defenses
```

Load and evaluate a saved run without further learning:

```powershell
rl-attack-defense `
  --method sa_ppo `
  --env-id CartPole-v1 `
  --load-model outputs/p2_defenses/CartPole-v1_sa_ppo_seed0/model.zip `
  --run-name CartPole-v1_sa_ppo_seed0_reload
```

Use `--continue-timesteps N` with `--load-model` to continue training. A
non-empty output bundle is rejected unless `--overwrite` is explicitly given.
The equivalent module entry point is
`python -m rl_attack.cli.defense_baseline`.

## Versioned experiment contracts

- `configs/experiments/p2_cartpole_defense_baselines.yaml`
- `configs/experiments/p2_highway_fast_defense_baselines.yaml`

Both contracts use at least five victim seeds, disjoint validation/test
cohorts, paired test episode seeds, clean/robust Pareto selection, and the P1
attack suite. Test seeds are forbidden during defense selection.

HighwayEnv's matrix observation is transformed explicitly with Gymnasium's
row-major `FlattenObservation` wrapper. The runtime manifest records both raw
and policy-input shapes so perturbation coordinates remain auditable.

## Claim boundary

P2 establishes reproducible implementations and weak-attack Pareto baselines.
It does not establish final robustness. No method is called robust until P3
adds Q/Safety-Critic PGD, strategically timed attacks, PA-AD or ATLA, separate
action-output attacks, and adaptive `worst-over-attacks` evaluation.
