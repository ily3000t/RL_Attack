# P4 Release — Semantic, Temporally-budgeted, Factorized Attack

Status: **implementation completed（已落实）; empirical effectiveness and
multi-seed statistical gates pending**

## Description（已落实）

P4 has implemented（已落实）the maintained `STFA` strong observation-attack
stack for frozen categorical Stable-Baselines3 PPO victims. The release covers
the sequential attack contract, hard temporal budgeting, factorized target
ontology, projected continuous optimization, bounded discrete semantic search,
SUMO/Highway policy-input semantics, learned safety critic and temporal
director, fixed-dataset training plumbing, strict artifacts, and a paired audit
boundary.

This is an implementation release. It does not claim that STFA is stronger than
PGD, MAD, Robust-Sarsa, or PA-AD; that any defense is robust; or that a SUMO
victim has been empirically compromised. A stable, immutable SUMO PPO victim is
not yet available for the formal effectiveness gate.

## Implemented attack contract

- Exact zero-based action factorization, including the SUMO 3 × 3 ontology and
  canonical sparse Highway five-action mapping.
- A per-episode hard ledger for `K`, minimum gap, and optional rolling-window
  limits. Selected zero-delta steps still consume temporal budget.
- Separate target action and actual adversarial action reporting.
- `full`, `flat`, `factor`, `safety`, `ce`, and `mad` objective variants with
  multi-step, multi-restart projected optimization.
- Explicit transfer, victim-adaptive, exact, EOT, and BPDA declarations.
- Independently measured continuous norms, discrete edit cost, temporal use,
  policy/gradient/projection/critic/director/transform cost.

SUMO discrete search uses an explicit immutable allowlist and deterministic
single-field legal-grid neighbors. Candidate comparison uses the same
objective, and stochastic EOT comparisons use common random numbers. This is a
bounded local semantic search, not exhaustive multi-edit enumeration.

## Implemented semantic contracts

The frozen SUMO projector maps physical-unit budgets to the exact 52-dimensional
policy input and enforces categorical grids, padding, dimensions, and neighbor
order. The Highway projector is built from a runtime observation descriptor and
freezes presence/padding semantics. Safety signals preserve source availability:
Highway does not synthesize TTC or DRAC, and SUMO metric-version mismatches fail
closed.

All such guarantees are policy-input schema guarantees, not certificates of
simulator-state realizability.

## Implemented learned-artifact plumbing

The critic and director use strict tensor contracts, immutable victim/space/
ontology bindings, dataset and adjacent-manifest hashes, environment and
normalization contracts, cost/label definitions, and deterministic
recomputation checks. Director artifacts additionally bind the exact critic,
temporal budget, and horizon.

`rl-attack-train-stfa` provides two fixed-data stages:

```powershell
rl-attack-train-stfa critic ...
rl-attack-train-stfa director ...
```

Inputs are strict NPZ datasets loaded without pickle. The command does not
collect rollouts and its run manifest is labelled as training-pipeline evidence,
not formal statistics. Checkpoint and sidecar publication is transactional;
overwrite requires an explicit flag.

## Implemented audit boundary

`rl-attack-p4-audit CONFIG --output-dir RUN_DIR` pins the PPO checkpoint and
policy-state hash, exact spaces, environment registry and assets,
normalization/cost contracts, factorization, projector, critic, director,
temporal ledger, seeds, and deterministic-argmax execution mode. Invalid output
cannot produce a robustness summary. Dependency injection is test-only and
always summary-ineligible.

The manifest separates algorithm-contract, real SB3 nine-action integration,
SUMO contract integration, and SUMO empirical effectiveness evidence. Checked-in
templates contain explicit unresolved-artifact sentinels and must be copied,
resolved with real files/hashes, and validated before a production run.

## Verification scope

The P4 suites exercise action ontology, temporal invariants, projection and
semantic repair, target-versus-actual action semantics, objective variants,
adaptive-mode declarations, discrete candidate search, critic/director
training and tamper rejection, strict dataset-driven CLI paths, real SB3
nine-action integration, audit failure behavior, and transactional artifacts.

Passing these tests establishes implementation and contract behavior. It is not
evidence of attack effect size or a robustness ranking.

## Remaining empirical gate

Before an effectiveness claim, the project must:

1. freeze independently trained victim cohorts and train one provenance-bound
   critic/director set per victim and declared contract;
2. pre-register matched P3/P4 budgets, ablations, convergence checks, and
   adaptive defense-aware attacks;
3. select hyperparameters on validation cohorts only;
4. run paired held-out seeds and aggregate at the victim-training-seed level;
5. report confidence intervals, safety outcomes, clean cost, measured compute,
   and episode-wise worst-over-attacks.

SUMO additionally requires a stable victim bundle, exact environment factory,
pinned scenario assets, and official artifact bindings. Until then the SUMO
implementation gate remains not ready and `sumo_empirical_effectiveness=false`.
