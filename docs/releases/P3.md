# P3 Release — Reproduced Strong-Attack Baselines and Audit

Status: **implementation completed（已落实）; multi-seed statistical benchmark pending**

## Description（已落实）

P3 has implemented（已落实）maintained strong observation attacks for frozen,
categorical Stable-Baselines3 PPO victims: a clean-room categorical adaptation
of Robust-Sarsa and a clean-room stochastic-PAMDP PA-AD path. The executable
audit evaluates PGD-CE, categorical MAD-PGD, Robust-Sarsa, and PA-AD under the
same epsilon profile, mutable mask, paired seeds, victim action mode, and hard
query/gradient budget. Learned attacker artifacts are bound to the exact victim,
and an invalid fallback can never be counted as robustness.

This release completes the code, contract, executable-smoke, and test gate. It
does not claim final multi-seed robustness rankings, official upstream code, or
an exact reproduction of the legacy experiment stacks.

## Implemented methods

### Robust-Sarsa categorical adaptation

- Collects on-policy SARSA transitions from a frozen SB3 PPO victim and trains
  a state-action critic with TD loss and joint state-action neighborhood
  robustness.
- Keeps the critic state fixed at the clean observation during attack and
  minimizes `sum_a pi(a | s_adv) Q_RS(s_clean, a)` inside the declared
  per-feature L-infinity set.
- Formal P3 evaluation uses `stochastic_sample`, where expected Q matches the
  execution distribution. A deterministic softmax surrogate is separately
  labelled and must not be pooled with stochastic results.
- Uses one-hot categorical actions and finite joint projected optimization; it
  does not claim the paper's continuous-action setting or convex-relaxation
  bound.

Fidelity: `clean_room_categorical_adaptation`; `paper_exact_reproduction=false`.

### PA-AD stochastic-PAMDP path

- Uses a trainable director in the zero-sum tangent space of the categorical
  policy simplex and an actor that realizes the selected direction inside the
  sensor perturbation contract.
- Implements the PAMDP loop: direction proposal, adversarial observation,
  stochastic victim action, negative victim reward, GAE, and PPO update.
- Formally supports only a stochastic categorical victim. Deterministic
  D-PAMDP requires a target-action director and the distinct `J_D` objective,
  so a deterministic request fails closed.
- One-step actor optimization is the paper-motivated approximation;
  multi-step/restarted PGD is explicitly an engineering extension.

Fidelity: `clean_room_algorithmic`; `paper_exact_reproduction=false`.

## Artifact and victim binding

Both learned attacks record and verify the victim checkpoint SHA-256, complete
in-memory policy-state SHA-256 (parameters and buffers), inference/freeze
evidence, attacker checkpoint SHA-256, strict sidecar manifest, training
evidence, observation/action contract, and victim action mode. The audit rejects
cross-victim reuse, missing or tampered sidecars, untrained learned attackers,
space mismatches, and invalid fallbacks.

PA-AD additionally binds the exact policy-input perturbation contract used for
training: observation shape/order, per-feature epsilon, validity bounds, and
mutable mask. A formal audit configuration contains zero as its control and at
most one non-zero epsilon. Each additional non-zero epsilon requires a director
trained and pinned for that exact victim and contract; one unconditioned
director is never reused across an epsilon sweep as if it were strongest-case
evidence.

## Executable audit

`rl-attack-strong-audit CONFIG --output-dir RUN_DIR` executes:

```text
victim checkpoint × epsilon ratio × paired episode seed × attack
```

For stochastic victims it uses audit-owned SHA-256-derived common random
numbers and inverse-CDF action sampling. PGD-CE, MAD-PGD, Robust-Sarsa, and
PA-AD share the same opportunity stream and fairness contract. Instrumented
policy calls determine actual cost. The primary result is the per-episode worst
return over the complete attack set, not the minimum of averaged tables.

Runs emit strict JSON/CSV episode data, paired return drops, CVaR, action flips,
method success, realized perturbations, measured query/gradient cost, available
safety metrics, bootstrap intervals, worst-over-attacks, hashes, lock files, and
Git provenance. Missing safety signals remain `null` with a reason.

Learned checkpoints are generated with:

```powershell
rl-attack-train-strong robust-sarsa ...
rl-attack-train-strong pa-ad ...
```

## Remaining statistical gate

Final robustness tables require fixed P2 victim checkpoints for multiple
independent seeds, a separately trained RS critic per victim, a PA-AD director
per victim and per non-zero epsilon contract, frozen selection/test cohorts,
the complete epsilon sweep assembled from separately pinned configurations,
and aggregation at the victim-training-seed level. These compute-heavy tables
remain pending; no robustness ranking is claimed by this implementation release.
