# P5 — RAPID-Guard proposed defense（已落实）

## Release status

P5 implements the Risk-Aware Policy-Invariance Defense (`RAPID-Guard`) as a
maintained algorithm, fixed-data training pipeline, immutable artifact bundle,
stateful Guard, and strict offline audit contract.

“Implemented（已落实）” means that the code paths, scientific claim boundaries,
provenance checks, failure behavior, and contract tests exist. It does not mean
that RAPID-Guard has passed its public-driving or SUMO statistical gate. No
strongest-defense, safety, or empirical robustness claim is made in this
release.

Full contract: [`../contracts/p5_rapid_guard.md`](../contracts/p5_rapid_guard.md).

## Implemented components

- temporal innovation, categorical Jensen--Shannon divergence, and one-step
  IBP margin-deficit detector channels;
- deterministic attack-exposed logistic fusion with explicit channel
  ablations;
- clean episode-maximum split-conformal threshold calibration;
- strict raw-only NPZ loading and recomputation of victim probabilities,
  logits, and IBP bounds from a frozen SB3 policy;
- a frozen residual-denoiser proposal whose output still requires projection;
- deterministic semantic-temporal line-search purification;
- transactional, per-episode trusted anchors;
- deterministic legal fallback with optional verified action-cost critic;
- optional, separately bound final safety-shield arbitration;
- a scoped BPDA identity purifier adapter that explicitly excludes hard gates;
- checkpoint/sidecar cross-binding and transactional publication;
- a strict 13-cell P1/P3/P4, non-adaptive/defense-aware offline audit.

The detector, denoiser, and training pipeline operate on policy inputs. The
purifier guarantees schema and temporal-envelope consistency only. Neither the
proposal nor projected result is claimed physically realizable.

## Dataset and artifact integrity

Fit and calibration datasets are separate immutable files. Episode and scenario
identifiers, three-frame window continuity, roles, reserved test cohorts,
environment, action ontology, normalization, projector, victim, detector
preprocessing, anchor, purifier, fallback, and IBP declarations are checked.
Object arrays and cached model-derived detector features are forbidden.

The frozen victim is reloaded by exact checkpoint hash; its complete policy
state is checked before and after recomputation and training. Bundle loading
revalidates checkpoint bytes, sidecar, embedded manifest, victim binding,
projector binding, detector state, conformal calibration, and denoiser proposal
binding.

Training output declares:

```text
training_plumbing_not_formal_robustness_result
```

It does not consume the reserved test cohort and is not a formal evaluation
artifact.

## Guard failure behavior

The current input is scored before any anchor update. Only validated
pass-through or accepted purification commits trusted state. A rejected
observation, component failure, fallback, or failed shield arbitration
preserves the previous anchor. Fallback also invalidates trusted-history
continuity until an explicit bound rebootstrap. Illegal actions, mutable
components, changed projector fingerprints, invalid critic output, and
broadened guarantee scopes fail closed.

The fallback guarantees a legal action only. The IBP component certifies the
clean greedy action only for a supported MLP and exact local input box. Neither
is a return or safety certificate.

The implemented runtime enforces two additional formal-row boundaries:

- every deployed preprocessing, history-bootstrap, projector, purifier,
  proposal, certificate, fallback/critic, and shield component must match the
  verified complete bundle rather than merely present a self-consistent hash;
- calibrated detection requires a caller-attested, attack-free prefix with two
  consecutive trusted frames from the current episode. No or single trusted
  frames fail closed before victim-policy or IBP queries; fallback breaks
  continuity until explicit rebootstrap. These warm-up/OOD decisions and their
  costs are reported separately outside H1 coverage. Repeated-first bootstrap
  is not supported.

Replacing any one component with a valid object from another bundle must fail
before an episode starts.

## Audit status

The offline P5 audit pins immutable episode rows, victim/defense/adaptive
attacker artifacts, frozen environment and method contracts, separate attack
query budgets, four disjoint seed cohorts, and explicit evidence scope. Each
test seed must contain:

```text
Clean
FGSM / PGD / MAD / Robust-Sarsa / PA-AD / STFA
  x non_adaptive / defense_aware
```

It computes independent episode-wise worst-return, collision, near-miss, and
safety-cost endpoints, clean cost, detector false positives, purifier
distortion, intervention/fallback/certificate statistics, latency, and
component accounting. Missing or invalid cells publish only an invalid,
summary-free manifest. Dependency-injected or test-scope rows can produce
integration evidence but are never eligible robustness evidence.

## Falsifiable empirical gate

The release pre-registers three claim families:

- H1: fused detector performance at a fixed clean false-positive operating
  point;
- H2: purifier recovery under held-out attacks with bounded clean distortion;
- H3: complete Guard worst-case safety and utility under clean-cost and latency
  constraints.

All require frozen multi-seed public-driving cohorts, per-defense adaptive
attackers, complete P1/P3/P4 matrices, gradient-masking checks, paired
confidence intervals, and registered failure thresholds. The implementation
release does not contain those results.

## SUMO boundary

`sumo_empirical_effectiveness=false` remains mandatory. A stable, immutable
SUMO PPO victim and official learned P5 bundle are not available. Current
contracts may test SUMO observation/action integration, but they cannot support
SUMO safety/effectiveness or PPO versus shield versus ACCVP conclusions.

## Commands

The console entry points expose every required hash-bound input without
importing WCDT. Inspect the exact arguments before constructing a run-specific
command:

```powershell
rl-attack-train-rapid-guard train --help
rl-attack-train-rapid-guard verify --help
rl-attack-p5-audit <resolved-p5-config.yaml> `
  --output-dir outputs/p5_rapid_guard_audit
```

All inputs must be replaced by real, exact hashes in a run-specific resolved
configuration. Checked-in method YAML is a contract template, not a result.

## Remaining statistical work

- independently trained victim and defense seeds;
- validation-only model, threshold, and budget selection;
- unseen and defense-aware P1/P3/P4 attacks trained outside the test cohort;
- detector-channel, purifier, adversarial-exposure, IBP, fallback, and shield
  ablations;
- attack convergence and gradient-obfuscation diagnostics;
- paired bootstrap intervals and corrected multiple-method comparisons;
- separate public-driving and later SUMO reports.

P5 becomes empirically complete only after those immutable result artifacts
exist and pass the full contract.
